# Preserve useful understanding

Persist only a reusable delta supported by accepted evidence, leaving unchanged sections untouched.
Use Home for systematic guidance useful across Workspaces and Workspace for finer project understanding, provenance, and provisional findings.
Reuse relevant documents already read, or search once before creating a new item for the same subject.
Keep Knowledge writes separate from the approval required for initial or material Machine Info changes.

For a new Workspace discovery inventory, include the root classification and execution-edge tables using contentTables; the Host renders their Markdown.
Use columns `["Entry", "Category", "Evidence tier"]` for classification and `["Project", "Edge", "Source file", "Active line", "Status"]` for edges.
Every census entry gets one classification row, with unread entries marked unclassified/census; keep selected entries partial when their purpose remains uncertain.
Use status direct only with an exact observed source file and verbatim active line that supports the claimed edge, otherwise partial with the missing fact stated.
An absent execution edge stays partial; an empty census need not produce a new Knowledge document.
For an existing document, replace only changed sections using exact heading paths from its latest read; unchanged tables need not be resent.

Replace identity-bearing roots with stable anchors such as <work-root> and <site-software-root> while retaining enough relative provenance to locate the source later.
Exclude endpoints, usernames, credentials, protected terminal content, licensed inputs, private source bodies, and large/raw results.
Do not persist an unapproved Machine Info proposal as settled Knowledge.
Read references/preserve-write.md only when a write is needed.
